هذا النظام عبارة عن تطبيق ويب متقدم (PWA) لحساب أسعار الطباعة الرقمية 
للمطبوعات المختلفة (كتب، مجلات، بروشورات، ملصقات، أوراق رسمية، رسائل).

المميزات الرئيسية:
- يعمل بدون اتصال بالإنترنت (Offline First)
- نظام أمان متقدم مع Google Authenticator
- قاعدة بيانات JSON (بدون SQL)
- حسابات تلقائية معقدة للأسعار
- واجهة عربية كاملة
- حماية من هجمات Brute Force
- تحديثات تلقائية للنظام

================================================================================
                    🔐 نظام الأمان والمصادقة
================================================================================

1. المصادقة الثنائية (2FA):
   - استخدام Google Authenticator
   - مكتبة otplib للتحقق من رموز OTP
   - Secret Key فريد لكل مستخدم

2. إدارة الجلسات:
   - express-session مع secret key
   - مدة الجلسة: 24 ساعة
   - resave: false
   - saveUninitialized: false

3. الحماية من Brute Force:
   - تتبع محاولات الدخول الفاشلة في failed-logins.json
   - قفل الحساب لمدة 12 ساعة بعد 3 محاولات فاشلة
   - Rate Limiting: 5 محاولات كل 15 دقيقة

4. Rate Limiting:
   ```javascript
   windowMs: 15 * 60 * 1000,  // 15 دقيقة
   max: 5,                     // 5 محاولات كأقصى حد
   message: 'Too many login attempts'
   ```

5. تأمين HTTP Headers:
   - Helmet middleware لتأمين الرؤوس
   - منع XSS, Clickjacking, MIME Sniffing

6. تخزين كلمات المرور:
   ⚠️ ملاحظة: حالياً يتم تخزين كلمات المرور كنص عادي
   🔔 توصية: استخدام bcrypt لتشفير كلمات المرور

1. papers.json (32 سجل)

الهيكل: Array of Arrays

مثال:

الاستخدام:

- حساب C2 (سعر الغلاف), C3 (سعر الطباعة)
- حساب C6 (سعر الورق الداخلي), C7 (سعر طباعة داخلي)

أنواع الورق:

3. books-magazines.html (897 سطر)
---------------------------------
الوظيفة: حساب أسعار الكتب والمجلات

الحقول الإلزامية:
- B1: الكمية
- B2: حجم الغلاف
- B3: نوع ورق الغلاف
- B4: نوع الطباعة (عادي/ملون)
- B6: حجم الورق الداخلي
- B7: نوع الورق الداخلي
- B8: عدد الصفحات الداخلية

آلية الحساب:
1. C2 = VLOOKUP(B3, papers.json, B2) → سعر ورق الغلاف
2. C3 = B1 × printPrice × (B4 == "ملون" ? 4 : 1) → تكلفة طباعة الغلاف
3. C4 = حساب السلفان (إن وُجد)
4. C5 = حساب الكبسات والثنيات
5. C6 = VLOOKUP(B7, papers.json, B6) → سعر الورق الداخلي
6. C7 = (B8 / 2) × B1 × printPrice → تكلفة طباعة داخلي
7. C8 = حساب التجليد
8. C9 = SUM(C2:C8) → التكلفة الكلية
9. C10 = C9 / B1 → تكلفة الوحدة
10. B10 = VLOOKUP(B1, values.json).decimal → نسبة الربح
11. B11 = C10 × B10 → الربح للوحدة
12. D6 = (C10 + B11) × B1 → السعر قبل الضريبة
13. E6 = D6 × (1 + vat) → السعر النهائي مع الضريبة

ميزات إضافية:
✅ نافذة التحقق الإلزامي (Error Modal)
✅ تنسيق أسماء الحقول بالأحمر والعريض
✅ منع الحساب عند وجود حقول فارغة
✅ زر طباعة
✅ زر حفظ
✅ زر مسح

استراتيجية التخزين المؤقت:
---------------------------

1. عند التثبيت (install):
   - مسح جميع الكاشات القديمة
   - تجنب تخزين الملفات مسبقاً
   - skipWaiting() فوراً

2. عند التفعيل (activate):
   - حذف جميع الكاشات القديمة
   - clients.claim() للسيطرة على جميع الصفحات
   - إرسال رسالة 'SW_UPDATED' لجميع العملاء

3. عند الطلب (fetch):
   - Network First لـ: index.html, categories.html, API endpoints
   - Cache First لـ: CSS, JS, Images, Fonts
   - الملفات المستثناة من الكاش: chrome-extension://, _next/

الملفات الحرجة (Network First):
- index.html
- categories.html
- /*.json
- /login

navigator.serviceWorker.addEventListener('message', (event) => {

function showUpdateNotification() {
  if (confirm('يوجد تحديث جديد. هل تريد تحديث الصفحة؟')) {

}

معادلة VLOOKUP (محاكاة في JavaScript):
---------------------------------------
```javascript
function vlookup(searchValue, array, returnColumn) {
  for (let row of array) {
    if (row[0] === searchValue) { // العمود الأول
      return row[returnColumn];
    }
  }
  return null;
}
```

حساب نسبة الربح من values.json:
--------------------------------
```javascript
function getProfitPercent(quantity) {
  let percent = 0;
  for (let i = values.length - 1; i >= 0; i--) {
    if (quantity >= values[i].value) {
      percent = values[i].decimal;
      break;
    }
  }
  return percent;
}
```

function calculateSelfan(type, size, quantity) {
  if (type === "بدون") return 0;

    if (selfanRow) {
      price = selfanRow[size_column];

  }
  
  return price * quantity;
}

                    🔄 دورة حياة الطلب (Request Lifecycle)
================================================================================

1. المستخدم يفتح النظام:
   ↓
2. Service Worker يتحقق من الكاش:
   ↓
3. إذا موجود → يُرجع من الكاش
   إذا غير موجود → يطلب من الشبكة
   ↓
4. index.html يُحمّل:
   ↓
5. المستخدم يُدخل البيانات (username, password, OTP):
   ↓
6. JavaScript يُرسل POST /login:
   ↓
7. server.js يتحقق من:
   - هل الحساب مقفول؟
   - هل كلمة السر صحيحة؟
   - هل OTP صحيح؟
   ↓
8. إذا نجح → إنشاء جلسة + إعادة توجيه لـ categories.html
   إذا فشل → زيادة failed-logins.json
   ↓
9. categories.html يُحمّل:
   ↓
10. المستخدم يختار نوع الحساب:
    ↓
11. الحاسبة المناسبة تُحمّل (books-magazines.html مثلاً):
    ↓
12. JavaScript يطلب البيانات:
    - GET /papers.json
    - GET /settings.json
    - GET /values.json
    ↓
13. المستخدم يُدخل بيانات الطلب:
    ↓
14. JavaScript يتحقق من الحقول الإلزامية:
    ↓
15. إذا ناقص → عرض Error Modal
    إذا كامل → تنفيذ الحسابات
    ↓
16. عرض النتيجة النهائية (D6/E6):
    ↓
17. المستخدم يطبع أو يحفظ:
    ↓
18. اكتمل الطلب ✅

   - تحقق من console.log للمتغيرات

   - Application Tab → Service Workers
   - تحقق من حالة التسجيل
   - تحقق من Cache Storage
   - افحص Console للرسائل

4. أخطاء الخادم:
   - تحقق من terminal logs
   - ابحث عن Error في سجلات Express
   - تحقق من /health endpoint

هذا النظام مصمم بعناية لتلبية احتياجات مطبعة رقمية. البنية معتمدة على

بيئات ذات اتصال ضعيف أو منقطع.

الكمية، نسبة الربح، الضريبة) لتقديم سعر نهائي دقيق.
